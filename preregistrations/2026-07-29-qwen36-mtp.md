# Pre-registration #71: the new-generation challenger — Qwen3.6-35B-A3B and the MTP question

**Author:** Federico Sciuca · **Date staked:** 2026-07-29, BEFORE the download starts. **STAKED.**

## Why this measurement

The hf-discover dry-run (feature branch, catalog of 39 models through remote headers + the
calibrated law) named exactly one candidate that could improve on this box's measured champion
(Qwen3.5-35B APEX-Mini, 21.52 tok/s, prereg #66): **Qwen3.6-35B-A3B**, the Apr-2026 successor in
the same 35B/3B-active MoE class, predicted ~17 raw — and it ships **MTP GGUF variants**
(model-integrated speculative decoding). The MoE-MTP cell of the speculation map was measured at
**0.76× — a loss — on the previous generation** (Law 6 arm S-e): the K+1-position verify batch
activates the union of experts on the CPU-resident path, and no acceptance rate pays that back.
The union tax is placement physics, not model quality. This prereg tests whether that scope
statement survives a model generation built WITH MTP in mind.

## Protocol

File: `unsloth/Qwen3.6-35B-A3B-MTP-GGUF` / `Qwen3.6-35B-A3B-UD-Q2_K_XL.gguf` (12.6 GB, ~2.87
effective bits — the K-quant pick per our own #52/#70 format findings, same size class as the
champion). Tool prediction captured from `plan --gguf` AFTER download, BEFORE any bench. One
session, clocks logged before/after (C-10 discipline). Arms:

- **A (champion control):** Qwen3.5-35B APEX-Mini re-run, tool-emitted split config, tg128.
- **B (challenger raw):** Qwen3.6-35B-A3B, tool-emitted split config, tg128 (MTP head inert
  under llama-bench).
- **C (MTP on):** same file, MTP speculative decoding enabled, novel-code prompt (the #67–#69
  standard prompt), temp 0, n≈192, generation tok/s.

Runtime risk, disclosed up front: the pristine llama.cpp build must load the qwen3.6 arch and
drive its MTP head. If either fails, the affected arm scores "blocked-by-runtime" — stated, not
silently dropped.

## Stakes

- **P-1 (the tool's band).** Arm B lands within plan's printed band of the captured prediction.
- **P-2 (THE MECHANISM — the union tax survives generations).** MTP does NOT pay on the MoE
  split placement: **C ≤ 1.05× B.** The tax is set by the verify batch's expert union on the
  CPU path — model generation and acceptance rate are not the binding variable.
- **P-3 (the ladder claim).** B ≥ 15 tok/s — the box gains a newer-generation 35B at usable
  speed either way. The A-vs-B raw delta is REPORTED, not staked: both files sit in the same
  physics class and the #66 under-promise pattern could land B anywhere in 16–22.

## KILL RULE

**If P-2 fails (C > 1.30× B), the union-tax scope statement is BROKEN on the new generation** —
D-09's MoE closure reopens, the register is amended, and the mechanism must be re-derived
(candidate: an MTP implementation that verifies against the SAME routed experts rather than
re-routing per position would erase the union). That would be the most valuable outcome of the
program's speculation track since #28 — published at full prominence. Between 1.05× and 1.30×:
P-2 misses softly, scored as "generation-dependent, mechanism partially eroded", and the map's
MoE cell gets a version qualifier. Misses publish like hits, as always.

**Wired into:** pending; the speculation map's MoE-MTP cell, `speculation_advice`, and the
discover catalog's Qwen3.6 entry score either way.
